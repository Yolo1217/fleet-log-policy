## 1. 单元测试与覆盖率

执行命令：

```bash
go vet ./...
go test -count=1 ./internal/fleetlog/... -coverpkg=./internal/fleetlog/... -coverprofile=coverage.out
go tool cover -func=coverage.out
```

结果（2026-11-13 重新采集，提交 `c2b2a51` 之后含演示接口加固）：

| 指标 | 结果 | 证据 |
| --- | --- | --- |
| `go vet ./...` | 通过（exit 0） | 部署脚本质量门禁日志、CI |
| 单元测试 | 5 个包全部通过 | `docs/evidence/unit-test-output.txt`（原始输出） |
| 整体语句覆盖率（`-coverpkg` 全部自编生产代码） | **88.5%**（门禁 ≥85%） | `docs/evidence/coverage.txt`（逐函数原始数据） |
| entity / model | 100.0% / 100.0% | `docs/evidence/coverage-per-package.txt` |
| handler | 89.8% | 同上 |
| repo | 89.0% | 同上 |
| service | 87.0% | 同上 |

覆盖率口径说明：使用 `-coverpkg=./internal/fleetlog/...` 统计**全部自编生产代码**（含数据库访问与 HTTP 处理，未自行排除任何包）；原始 `.out` 文件由 CI 每次 `go test` 重新生成并作为 artifact 上传。

**口径陷阱（独立测试 Agent 复核时发现）**：多包测试会让同一代码块在 profile 中出现多条记录（未执行该块的包写 `count=0`），若逐行累加会被稀释成约 31.8% 的错误结论；必须按代码块求和（`go tool cover` 内部即如此）才能得到 88.5%。按包聚合的正确结果见 `docs/evidence/coverage-per-package.txt`。此前报告与 `unit-test-output.txt` 里的按包数值来自"某包测试覆盖全部内部包"的另一口径，已统一替换，三套数值不再并存。
