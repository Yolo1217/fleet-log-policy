# 题目 09 原型设计 — 车队日志策略申请、审批、分批发布与结果核查

> 原型文件：`docs/09-原型.html`（单文件、浏览器直接打开即可点击操作，无需依赖）。
> 性质说明：原型为**静态演示**，仅用于确认页面结构、角色入口与状态展示；数据为示意值，不代表真实业务实现，不替代后续接口与数据库。

## 1. 设计目标

1. 让四类角色（研发申请人、审批负责人、发布运营、模拟车辆）各自看到自己该操作的入口，且越权按钮不可用。
2. 让**"已下发 ≠ 已生效"**在页面上可见：期望值与生效值分列，失败/超时/未确认各自可解释。
3. 覆盖题面要求的 4 类页面：申请与审批、试点与推广操作、逐车进度核查、恢复结果；附加异常留痕页便于验收。

## 2. 页面结构

| 页签 | 页面 | 主要角色 | 关键内容 |
| --- | --- | --- | --- |
| ① | 申请与审批 | 研发申请人、审批负责人 | 新建申请（原因、5 台车、间隔 10～300）、申请列表、批准/退回、历史版本、已批准参数锁定 |
| ② | 试点与推广操作 | 发布运营、审批负责人 | 活动状态机流程条、发起试点（2 台）、确认推广（3 台）、停止、批准恢复；试点结果两车表 |
| ③ | 逐车进度核查 | 负责人、运营（只读核查） | 5 台车逐车：活动前值、期望值（版本+间隔）、生效值（版本+间隔）、状态、失败/超时原因、下发与回执时间；车辆视角拉取演示 |
| ④ | 恢复结果 | 审批负责人 | 恢复目标（活动前值）、恢复版本、恢复后生效值、已恢复/恢复失败/未确认；存在未确认时"全部恢复"按钮置灰 |
| ⑤ | 异常留痕 | 负责人、运营 | 越权推广、重复回执、旧版本回执、跨车回执、未知版本、未鉴权 6 类异常记录表 + 原型交互日志 |

## 3. 页面状态说明（原型可点击演示）

| 交互 | 演示的状态变化 | 对应需求条目 |
| --- | --- | --- |
| 提交申请 | 原因空/间隔越界 → 校验失败提示；合法 → 生成待审批申请 | 规则 1、边界 2 |
| 批准 / 退回 | 批准 → 已批准（参数锁定）；退回 → 已退回（可修改后再提交，保留历史版本） | 规则 1 |
| 发起试点 + 两支模拟按钮 | 已批准 → 试点中（TE-01、TE-02）；点"两台均成功" → 试点成功（可推广）；点"试点车超时" → 已暂停（不可推广） | 规则 2、3、边界 12 |
| 确认推广（试点未完成时点击） | 拒绝并提示"试点未全部成功"+ 写入异常留痕 | 规则 3、边界 4 |
| 负责人停止 | 已暂停/推广中 → 已停止；仅阻止未发送部分，已发/已生效记录保留 | 规则 7、边界 13 |
| 批准恢复 | 已停止 → 恢复中；按车生成更高版本，目标为活动前 60 秒 | 规则 7、假设 A4 |
| 逐车表格 | 5 台车分别展示 成功 / 超时 / 失败 / 未确认 / 待下发 五种状态 | 规则 4、6、8 |
| 车辆视角拉取 | 选车拉取 → 只返回面向本车的最新已发布版本；TE-05 试点期/停止后拿不到活动版本 | 规则 4、边界 5 |
| 恢复结果页 | 有未确认/失败车辆时"标记全部恢复"置灰 | 规则 8、验收条件 3 |

## 4. 与"五个必须演示场景"的对应

| 场景 | 原型中的体现 |
| --- | --- |
| 正常推广 | ② 页流程条 已批准→试点中→试点成功→推广中→待结案→已完成；③ 页逐车生效值=期望值 |
| 审批与试点分支 | ① 页退回再提交；② 页 TE-02 超时→已暂停→停止；③ 页 TE-05 待下发（未收到配置） |
| 恢复分支 | ④ 页区分已恢复 / 恢复失败 / 未确认；"全部恢复"按钮置灰 |
| 网络分支 | ⑤ 页 6 类异常留痕；③ 页 TE-04 旧版本回执不改生效值 |
| 结果核查 | ③ 页同一活动内同时存在成功、失败、超时、未确认、待下发，不能只看活动总状态 |

## 5. 刻意不做的部分（范围边界）

- 不做视觉设计与响应式打磨（题面只要求可操作的最小页面）。
- 原型不含真实鉴权、数据库与状态机实现；这些在开发阶段由后端 service 层保证（原型中的"按钮置灰"最终必须由服务端校验兜底，不能只靠前端）。
- 不做车辆在线状态机（离线用"晚拉取/晚回执"模拟，假设 A6）。

## 6. 使用方式

用浏览器打开 `docs/09-原型.html`，按页签切换；② 页发起试点后可分别点击"两台均回执成功"或"试点车超时"演示两条分支。所有点击会在 ⑤ 页"操作日志"中记录，便于讲解时回看操作顺序。
