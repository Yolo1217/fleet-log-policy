# 题目 09 业务规则与可断言口径

来源：《Go 项目业务场景题》题目 09「需要完成的业务范围与规则」第 1～8 条，原文要点与可执行断言一一对应。

## 规则原文要点

1. 申请必须包含原因、五台目标车辆和新间隔（10～300 秒，初始 60 秒），**审批人不能是申请人**；退回后可修改再提交；**批准后的参数不可原地修改**。
2. 同一车队同时只允许**一个未结束发布活动**；运营先选**其中两台**试点，其余车辆**不得提前获得**该活动配置。
3. 两台试点**均成功**后才可推广至剩余三台；试点失败或超时则**暂停推进**，负责人可停止活动，**不得绕过检查直接推广**。
4. 车辆只取得**面向自己的最新已发布版本**；每车版本递增，分别保存**期望值**与**已生效值**；下发记录不代表车端生效。
5. 回执须**鉴权**且对应**向其发布的版本**；重复成功**不重复记账**；旧版本**不能覆盖**新生效版本；未知版本与**跨车回执须拒绝并记录**。
6. 发布 60 秒未获有效回执显示**超时**；当前期望版本的**迟到成功可更新结果并保留超时历史**；失败**不改变**此前生效值；已停止活动**不因迟到回执自动重启**。
7. 停止活动**仅阻止未发布部分**继续下发，不能抹掉已发布和实际生效记录；负责人批准恢复后，运营为**曾发布过配置的车辆**创建新的恢复版本，目标为**各车活动前设置**。
8. 全部目标车辆确认成功才可记为完成；停止时须保留**已发/未发范围**；所有需恢复车辆**均确认**后才可记为恢复完成；逐车核查须能区分成功、失败与未确认，存在未确认项时**不得显示全部恢复**。

## 断言映射（脚本对应条目）

| 规则 | 断言 | 期望 |
| --- | --- | --- |
| 1 | 未登录提交申请 | 401 |
| 1 | 运营角色提交申请 | 403 |
| 1 | 间隔 9 / 301 | 400 |
| 1 | 原因为空 | 400 |
| 1 | 负责人批准本人申请 | 403 + `self_approval` 留痕 |
| 1 | 退回未填原因 | 400；退回后可重提且 `version_no` 递增、历史保留 |
| 1 | 已批准申请再次批准 | 409 |
| 2 | 同车队第二个申请批准 | 409 |
| 2 | 试点选择 1 台或 3 台 | 400 |
| 2 | 试点含外车队车辆 | 400 |
| 2 | 试点期其余 3 台拉取配置 | 不含活动版本与活动间隔 |
| 3 | 试点未全部成功即推广 | 409 + `illegal_promote` 留痕 |
| 3 | 试点超时后活动状态 | `paused`，且推广继续被拒 |
| 4 | 试点车版本号 | 从 1 起单调递增；推广后剩余车各自从 1 起 |
| 4 | 已下发未回执时 | 期望值=新值，生效值=旧值（60） |
| 5 | 无车辆凭证 / 伪造凭证 | 401 |
| 5 | 回执他车版本 | 403 + `cross_vehicle` 留痕 |
| 5 | 回执未知版本 | 404 + `unknown_version` 留痕 |
| 5 | 重复成功回执 | `duplicate=true`，回执表新增记录但生效值不重复变更 |
| 5 | 旧版本回执晚到 | `ignored=true`，生效值不被覆盖 |
| 6 | 超过阈值未回执 | 该车 `timeout`，活动 `paused` |
| 6 | 超时后当前版本成功回执 | 生效值更新、`late_success=true`、活动仍 `paused` |
| 6 | 失败回执 | 生效值保持活动前值 |
| 7 | 停止未填原因 | 400 |
| 7 | 停止后范围 | `dispatched` 保留已发车，`undispatched` 保留未发车 |
| 7 | 停止后车端拉取 | 仍返回车端已生效值，不假装已撤销 |
| 7 | 批准恢复 | 仅曾发布车生成**更高版本**，目标=活动前值 60 |
| 8 | 存在未确认项时标记恢复完成 | 409 |
| 8 | 全部确认后恢复完成 | `restored` 且 `all_recovered=true` |
| 8 | 未全部成功时结案 | 409 |
| 8 | 全部成功后结案 | `completed` 且 `all_succeeded=true` |
