# 题目 09 验收检查清单

来源：《Go 项目业务场景题》第一部分「6. 验收要求」、第 8 节 Git 与流程要求，以及题目 09 的 8 条业务规则。

## A. 需求与业务规则（对应规则 1～8）

| 编号 | 检查项 | 判定口径 |
| --- | --- | --- |
| A1 | 申请含原因、5 台目标车、10～300 整数秒间隔 | 越界与空原因被拒；合法申请生成待审批记录 |
| A2 | 审批人不能是申请人 | 负责人审批本人申请返回 403 并留痕 |
| A3 | 退回可修改再提交，批准后参数不可改 | 退回后 `version_no` 递增且历史保留；已批准再重提被拒 |
| A4 | 同车队同时仅一个未结束活动 | 第二个申请批准返回 409 |
| A5 | 试点固定两台，其余车不提前获得 | 试点 1/3 台被拒；其余 3 台拉取不含活动版本 |
| A6 | 试点均成功才可推广 | 未成功推广返回 409 并留痕 `illegal_promote` |
| A7 | 每车版本递增，期望值与生效值分离 | 拉取返回期望值；未回执前生效值保持旧值 |
| A8 | 回执鉴权、对应版本、幂等、拒绝跨车/未知 | 401/403/404 与 `duplicate`/`cross_vehicle`/`unknown_version` |
| A9 | 旧版本不覆盖新生效值 | 旧版本回执 `ignored=true`，生效值不变 |
| A10 | 超时显示，迟到成功更新并保留超时历史 | 车内状态 `超时`→`成功` + `late_success=true` |
| A11 | 失败不改变生效值，停止不自动重启 | 失败回执后 applied 不变；活动仍 `paused` |
| A12 | 停止保留已发/未发范围，不抹掉生效记录 | `dispatched_vehicles`/`undispatched_vehicles` 正确 |
| A13 | 恢复仅针对曾发布车、版本更高、目标为活动前值 | 恢复行 `expected=60`、`expected_version>1` |
| A14 | 存在未确认项不得显示全部恢复 | 恢复完成接口返回 409 |
| A15 | 全部成功才可结案 | 未全部成功结案返回 409 |
| A16 | 逐车核查含前值/期望值/生效值/状态/原因 | 活动视图逐车字段齐全，非仅活动总状态 |

## B. 测试与质量

| 编号 | 检查项 | 判定口径 |
| --- | --- | --- |
| B1 | `go build ./...` 通过 | exit 0 |
| B2 | `go vet ./...` 通过 | exit 0 |
| B3 | 单元测试全部通过 | `go test ./internal/fleetlog/...` 无 FAIL |
| B4 | 自编生产代码覆盖率 ≥85% | `-coverpkg=./internal/fleetlog/...` 的 total |
| B5 | 覆盖成功/失败/超时/重复/跨车/旧版本/停止/恢复/结案 | 测试函数或业务核查脚本中可数 |
| B6 | 并发验证 | 并发用例通过；`-race` 不可用时记 WARN 并说明 |

## C. 交付物与流程

| 编号 | 检查项 | 判定口径 |
| --- | --- | --- |
| C1 | 业务提交在 `dev/09`，`main` 仅初始化 | `git log main` 仅初始化提交 |
| C2 | 分支已推送且与本地一致 | `git rev-parse` 本地与 `origin/dev/09` 相同 |
| C3 | 文档齐全 | 需求分析、原型、任务清单、建仓记录、开发记录存在 |
| C4 | 页面可操作 | `web/index.html`、`web/vehicle.html` 存在且接口可用 |
| C5 | 至少两个自编 Skill（业务 + 验收） | `.codebuddy/skills/*/SKILL.md` 各含用途/触发/输入/步骤/输出/失败处理/完成标准 |
| C6 | `skill-usage.md` 汇总实际调用 | 含名称来源版本、使用原因、输入输出、调用记录位置 |
| C7 | 至少一次"Skill 发现问题 → 修正 → 复检" | 报告中保留前后两次结论与修复提交 |
| C8 | CI 流水线与部署证据 | `.github/workflows` 存在且运行成功；部署可访问 |
| C9 | 提交信息规范 | `feat`/`fix`/`docs`/`test` + 版本 + 描述；工作项编号偏差须记录 |
