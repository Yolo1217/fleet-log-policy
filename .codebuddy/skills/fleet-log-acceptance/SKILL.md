# 题目 09 交付物验收检查

## 用途

把题面「第一部分 6. 验收要求」和「题目 09 规则 1～8」转成可执行检查项，一次性采集 Git、测试、覆盖率、文档、Skill 证据，输出可直接贴进验收报告的结果表。检查只读取事实（命令输出、文件存在性、接口响应），不臆测实现质量。

## 触发场景

- 开发分支准备发起 PR 前的自检。
- 教师或他人要求"按题面验收"时，需要给出可复算的检查结论。
- 修复缺陷后复验受影响的检查项。

## 输入

| 输入 | 必填 | 说明 |
| --- | --- | --- |
| `--repo` | 否 | 仓库根目录，默认按脚本位置推断 |
| `--coverage-gate` | 否 | 覆盖率门禁，默认 85 |
| `--report` | 否 | 输出 Markdown 报告路径 |
| `--skip-tests` | 否 | 跳过 Go 测试（仅做静态与 Git 核查） |

## 执行步骤

1. 运行 `scripts/collect_evidence.py`，脚本依次执行：Git 状态与分支核查 → 必需文件核查 → `go vet` → `go test -count=1` + 覆盖率采集 → 边界用例关键词核查 → Skill 与记录核查 → CI/推送核查。
2. 逐项对照输出，把 FAIL 项转成缺陷清单（含期望值、实际值、复现命令）。
3. 修复后重跑同一命令（不要更换口径），保留前后两份报告作为整改证据。
4. 报告中 WARN 项须写明原因与处理决定，不得视为通过。

```bash
python .codebuddy/skills/fleet-log-acceptance/scripts/collect_evidence.py --report docs/evidence/acceptance-report.md
```

## 输出格式

```markdown
| 类别 | 检查项 | 结论 | 证据 |
| --- | --- | --- | --- |
| Git | 业务提交位于 dev/09 且已推送 | PASS | dev/09=a1b2c3d, origin/dev/09=a1b2c3d |
| 测试 | 单元测试全部通过 | PASS | 5 个包 ok |
| 覆盖率 | 生产代码整体覆盖率 ≥85% | PASS | 87.2% |
| 流程 | CI 工作流存在 | FAIL | .github/workflows 缺失 |
```

同时输出汇总行：`PASS x / WARN y / FAIL z`，FAIL 非 0 时退出码为 1。

## 失败处理

- `go vet`/测试失败：直接判 FAIL，附编译或断言输出前 20 行，不得只写"失败"。
- 覆盖率不足：给出未覆盖函数清单（`go tool cover -func` 中 0% 项），供定向补测。
- 缺少 Skill 记录或 `skill-usage.md`：判 FAIL；仅写了 Skill 文件但没有调用记录同样不算通过。
- 无法执行 `-race`（无 cgo/gcc）：记为 WARN 并注明环境原因，同时要求提供并发用例证据，禁止伪造竞态检测结果。
- 检查环境不洁（有历史数据库、端口被占）：先清理再复跑，报告中注明清理动作。

## 完成标准

1. 报告中 FAIL 数为 0；WARN 项均已写明原因与替代证据。
2. 覆盖率、Git 分支、异常路径、Skill 记录四类检查全部有实际命令输出作证据。
3. 报告文件保存到 `docs/evidence/`，并在 PR 描述中引用路径。
